# 홈페이지 이식 안내 — 설명회 슬라이드 키트

원장님이 홈페이지에서 설명회 주제 · 내용을 넣으면 Claude가 덱(HTML)을 쓰고, 이 키트가 그 덱을 그려 편집 가능한 PPTX로 내보내는 흐름을 전제로 쓴 문서입니다. 홈페이지 코드 구조는 개발자가 정합니다 — 여기서는 키트 쪽에서 정해 둔 것과 권장만 적습니다. (2026-10-23)

## 1. 흐름

> 홈페이지 '설명회 설계' 5단계(PPT 만들기)에 붙일 때의 재료 · 차이 · 레이아웃 대응표는 `docs/STEP5-INTEGRATION.md`.

```
원장님 입력(주제 · 학년 · 내용 · 학원 정보 · 학원 메인 컬러)
  ① Claude: 장 구성표(JSON)      프롬프트 = PROMPT.md + PROMPT-PARTS.md + 예시 덱 + PROMPT-PLAN.md + 요청
     → checkPlan(구성표, 요청, parts.json)  문제 있으면 문제 목록을 같은 대화에 돌려보내 다시(최대 2번)
  ② Claude: 구성표대로 덱 HTML (같은 대화에 이어서)
  ③ 키트가 덱을 그림(?brand=학원색) → window.slideCheck()
     → 걸린 장이 있으면 buildFixRequest(덱, 검사) 글 + PROMPT-FIX.md로 그 장만 다시 쓰게
     → parseFixResponse(답) → replaceSections(덱, …)로 바꿔 끼우고 다시 그려 검사(최대 2번, 그래도 걸리면 그대로)
  ④ 검사를 통과한 덱을 장마다 사진(960×540)으로 찍어 PROMPT-REVIEW.md와 함께 보냄 → 답('N장: 문제 — 방향' 줄, 최대 5장)
     → 그 줄들을 검사 문장 대신 buildFixRequest에 넣어 ③과 같이 다시 쓰기 → 다시 그려 검사(한 번)
  → 'PPT로 내보내기' (브라우저에서 kit/pptx.js — 서버 없이 브라우저에서, 글꼴 포함)
```

- ① · ③ 도우미는 모두 `slide/plan.js`(DOM 없이 글자만 다룸 — 브라우저 · 서버 어디서나): `checkPlan` · `buildFixRequest` · `parseFixResponse` · `replaceSections` · `parseSections`. 부품 이름 목록 `slide/parts.json`은 `npm run prompt-parts`가 `PROMPT-PARTS.md`와 함께 만듭니다.
- 이 흐름을 그대로 흉내 내는 시험 스크립트: `node scripts/slide-plan-check.mjs --plan 구성표.json --request 요청.txt` · `node scripts/slide-fix.mjs --deck 덱 --out 요청.md` / `--apply 답.html`.
- ④ 사진은 브라우저에서 키트가 이미 쓰는 html-to-image로 `section.slide`마다 찍으면 됩니다(시험 스크립트는 `slide-fix.mjs --shots 폴더`).

### 로컬 덱과 나란히 비교(2026-10-23, ① ~ ④ 전체)
여기서 만든 예시 덱(내신 `seminar-midterm` · 사회 `seminar-social`)과 같은 내용의 요청을 홈페이지 방식으로 다시 쓰게 했습니다(그 덱은 예시로 주지 않음).
- 그림 도식 비율(사진 장을 뺀 내지 중 내용 자체를 보여 주는 그림): 로컬 63% · 71% ↔ 홈페이지 방식 Sonnet 67% · 67%, Opus 75% · 64%. 그림 도식 비율 검사를 넣기 전 시험 덱은 23 ~ 36%였습니다.
- 도식 구성도 로컬 덱과 거의 같았습니다(책 쌓기 · 시험 범위 · OMR · 성적 분포 곡선 · 공부 순환 · 달력 / 축척 자 · 기후 그래프 · 위도 경도 · 시차 시계 · 로드맵).
- 자동 검사는 넷 모두 0건. 사진 점검이 장마다 1 ~ 4장을 더 고쳤습니다(이름 두 줄 꺾임 · 메모가 값을 가림 · 같은 숫자 되풀이 · 후기 하나만 떠 있음 · 만점처럼 보이는 막대).
- 요청에 숫자 · 사례가 넉넉할수록 로컬과 비슷해집니다 — 홈페이지 입력 화면에서 학원 실적 · 수업 방식 · 일정 · 후기를 칸으로 받기를 권합니다.

### 3단계 시험 결과(2026-10-23)
같은 요청(중2 수학 서술형 설명회)으로 ① → ② → ③을 돌렸습니다.
- Sonnet 5.5: 구성표 첫 검사 통과(20장, 도식 17종) → HTML 첫 검사 2장 걸림(도식 44% · 흰 도형 없음) → 다시 쓰기 1번에 통과. 이후 넣은 '대제목 숫자 되풀이' 검사에 11장이 걸려 고쳤고, 새 11장이 한 번 더 걸려 두 번째 다시 쓰기에 통과.
- Opus 5.5: 구성표에서 환산식의 '× 100'이 지어낸 숫자로 오검출(검사를 고침) → HTML 첫 검사 1장 걸림(도식 40%) → 다시 쓰기 1번에 통과.
- 두 모델 모두 최종 검사 0건. 한 번에 쓰던 때(경고 2 ~ 3장)보다 깨끗하고, 구성표 덕에 도식이 겹치지 않았습니다(17종 · 16종). 검사가 못 잡는 약한 장(내용이 적은 수업 시간 띠 등)은 남을 수 있어 원장님 마무리를 권합니다.

## 2. 덱 HTML 형식 (Claude가 써야 하는 결과)

- `<section class="slide">…</section>`를 장마다 이어 붙인 HTML 조각 하나. `<html>` · `<head>` · 스타일 · 스크립트는 쓰지 않습니다 — 글자 크기 · 색 · 배치는 모두 `slide.css`와 `main.js`가 정합니다.
- 장 종류: 표지 `section.slide.s-cover`, 장 표지 `section.slide.s-section`, 내지(머리 `header.s-head` + 본문 `div.s-body > div.s-grid > div.s-m …`), 마감(`.s-cta`). 형식은 `slide/examples/seminar-korean.html`(기준 덱)을 그대로 따르면 됩니다.
- 부품(도식)은 `slide/PARTS.md`에 있는 클래스만 씁니다. 사진은 넣지 않고 사진 자리(`figure.m-photo[data-kind][data-hint]`)만 둡니다 — 원장님이 PPT에서 '그림 바꾸기'로 넣습니다.
- 학원 메인 컬러는 덱에 쓰지 않습니다 — 화면을 열 때 `?brand=#RRGGBB`로 넘기면 키트가 적용합니다(`docs/BRAND-COLOR.md`).

## 3. 프롬프트 구성과 캐시

| 순서 | 내용 | 대략 크기 | 캐시 |
|---|---|---|---|
| 1 | 덱 쓰기 규칙 `slide/PROMPT.md` | 약 3천 토큰 | ✅ |
| 2 | 부품 마크업 표 `slide/PROMPT-PARTS.md`(자동 생성) | 약 4만~5만 토큰 | ✅ ← 캐시 표시 |
| 3 | 기준 덱 `seminar-korean` + 주제 예시 1벌(`slide/examples/deck-types.json`) | 약 1만~2만 토큰 | ✅ ← 캐시 표시(주제마다 따로 쌓임) |
| 4 | 이번 요청: 주제 · 학년 · 내용 · 학원 이름 · 연락처 | 적음 | ✗ |

- **프롬프트에는 `CLAUDE.md` · `slide/PARTS.md`를 넣지 않습니다** — 둘은 키트를 고치는 사람용(디자인 이유 · 수치 · 고친 기록)이라 덱 쓰기엔 잡음이 많습니다. 덱 쓰기에 필요한 것만 `PROMPT.md`(규칙)와 `PROMPT-PARTS.md`(부품마다 예시 덱에서 실제로 쓰인 마크업 하나)에 있습니다.
- `PROMPT-PARTS.md`는 예시 덱에서 자동으로 뽑습니다 — 예시 덱 · 부품이 바뀌면 `npm run prompt-parts`로 다시 만들고, 바뀐 파일을 프롬프트에 넣으면 캐시가 한 번 새로 쌓입니다.
- 크기는 글자 수로 어림한 값입니다. 정확한 값은 `messages.count_tokens`로 한 번 재 주세요.
- 캐시는 앞에서부터 글자 하나까지 같아야 맞습니다. 날짜 · 원장님 이름처럼 바뀌는 것은 4번(맨 뒤)에만 둡니다. 1 · 2를 모든 주제가 같이 쓰도록 캐시 표시를 2번 끝에 하나, 3번 끝에 하나 둡니다.
- `deck-types.json`의 `notForPrompt`(견본 · 비교용 덱)는 프롬프트에 넣지 않습니다. 표에 없는 주제는 `fallback`.
- 피할 것: ① 고쳐 달라는 요청마다 덱 전체를 다시 쓰기 → **바뀐 장만 다시 쓰게**(그 장의 `<section>`만 받아 바꿔 끼우기) ② 검사 → 다시 쓰기 반복을 여러 번 자동으로 돌리기 → 한두 번으로 제한 ③ 예시 덱을 많이 넣기 → 표대로 1~2벌.
- 모델 선택(Opus · Sonnet)은 품질을 같은 요청 몇 개로 비교해 정하는 것을 권합니다. 이 키트의 예시 덱은 모두 Opus 계열로 만들었습니다.

## 4. 덱이 지켜야 할 것 (프롬프트에 꼭 남길 것)

`slide/PROMPT.md`에 다 있지만, 품질에 가장 크게 영향을 준 것만 고르면:
- 내지 머리 = 목차 표시 + 대제목 한 줄(부연설명 ✗), 결론은 대제목에.
- 한 장 = 도식 하나, 같은 주 도식은 한 덱에 두 번까지 · 바로 옆 장 연속 ✗.
- 도식에 덱에 없는 정보(숫자 · 주장)를 지어 넣지 않기.
- 새 덱에는 사진 자리 장 2~4장(강사 · 교재 · 수업 장면 · 아이 작품).
- 흐름 9단계(공감대 → 가능성 → 성과 · 전문성 → 공통 문제 → 핵심 원리 → 객관적 근거 → 전략 · 커리큘럼 → 성공 사례 → 운영 · 관리), 20장 안팎 — 요청에 숫자 · 후기가 없으면 그 단계를 줄이거나 뺌.

### 시험 결과(2026-10-23)
같은 요청(중2 수학 서술형 설명회)을 이 프롬프트로 한 번에 쓰게 해서 키트로 그려 봤습니다. Sonnet 5.5 18장 · Opus 5.5 21장 모두 덱 형식 · 흐름 · 사진 자리 · 지어내기 금지를 지켰고, 검사 경고는 Sonnet 0건 · Opus 2건(문장 분석 넘침 · 주간 계획 작음 — 주간 계획은 키트에서 고침)이었습니다. 예전처럼 `CLAUDE.md` + `PARTS.md`를 넣었을 때는 마크업이 없는 부품을 짐작해 써서 깨진 장이 2~3장씩 나왔습니다. 그래도 예시 덱만큼 다양한 도식(주제다운 그림)은 덜 나오므로, 원장님이 스튜디오에서 마무리하는 흐름을 권합니다.

## 5. 검사

- 덱을 그린 화면에서 `window.slideCheck()`가 문제 목록(문자열 배열)을 돌려줍니다 — 넘침 · 정렬 · 도식 크기(45%) · 반복 도식 · 글자 대비 등. 빈 배열이면 통과.
- 눈에 보이는 무게 중심은 `scripts/slide-shot.mjs --weights 1`로 후보만 알려 줍니다(자동 실패 아님).
- 검사는 통과해도 디자이너가 사진으로 한 번 더 본 뒤 고친 것들이 많았습니다(CLAUDE.md '보여 드리기 전 점검표'). 홈페이지에서는 원장님이 스튜디오 '글자 고치기'와 PPT에서 마무리한다고 보고, 자동 반복은 줄이는 것을 권합니다.

## 6. PPT 내보내기

- `kit/pptx.js` `deckToPptx(slides, { title })` → PptxGenJS 문서. 스튜디오의 'PPT로 내보내기'가 이걸 부릅니다. 모두 브라우저에서 돕니다.
- 도형은 PPT 도형, 글자는 편집 가능한 글상자(자동 줄바꿈 끔 + 상자 크기 자동 맞춤), SVG 도식 · 사진 자리 · 아이콘은 그림 한 장. 그래프 값처럼 고칠 글자는 그림 밖 글상자로 꺼내 둡니다.
- Pretendard(쓴 굵기만, 하위 집합)를 PPTX 안에 넣습니다(`kit/pptx-fonts.js`, 약 +0.1MB) — 원장님 PC에 글꼴이 없어도 같은 모양.
- 외부에서 불러오는 것(CDN, 버전 고정): Pretendard 웹 글꼴 · html-to-image 1.11.11 · PptxGenJS 3.12.0 · Pretendard TTF 1.3.9 · harfbuzzjs 0.4.7(글꼴 하위 집합). 홈페이지에서 CDN을 막으면 이 파일들을 함께 올려 주소를 바꿔 주세요.
