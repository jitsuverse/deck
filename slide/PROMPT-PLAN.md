# 장 구성표 먼저 쓰기 (덱을 쓰는 Claude용 — 1단계)

HTML을 쓰기 전에 **장 구성표(JSON)만** 먼저 낸다. 홈페이지가 코드로 검사(`slide/plan.js checkPlan`)해서 문제가 있으면 문제 목록과 함께 돌려보낸다 — 그 목록대로 구성표를 고쳐 다시 낸다. 통과하면 2단계에서 그 구성표대로 HTML을 쓴다(`PROMPT.md` 규칙 · `PROMPT-PARTS.md` 마크업 그대로).

## 형식

JSON 하나만 답한다(설명 글 ✗).

```json
{
  "slides": [
    { "kind": "cover", "title": "중2 수학 서술형,\n풀이 쓰는 법이 점수예요", "icon": "pencil" },
    { "kind": "inner", "beat": "b1", "emotion": "seen", "step": "공감대", "index": "학부모님의 고민", "title": "상담에서 가장 많이 듣는 말이에요", "part": ".s-dialog", "support": null, "photo": false, "facts": [] },
    { "kind": "inner", "step": "성과 · 전문성", "index": "우리가 해 온 일", "title": "서술형 평균이 9점 올랐어요", "part": ".m-orbs", "support": ".m-caption", "photo": false, "facts": ["48명", "12점", "21점", "25점 만점", "9점 = 21점 - 12점"] },
    { "kind": "section", "title": "서술형은 풀이를 채점해요" },
    { "kind": "cta", "title": "첫걸음은 서술형 진단 한 번이에요" }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `kind` | `cover` 표지 · `section` 장 표지 · `inner` 내지 · `cta` 마감 |
| `beat` | 대본이 있으면 그 장의 꼭지 id(`[beatId: …]` 그대로) — 꼭지 순서대로, 빠짐없이, 꼭지마다 내지 1 ~ 2장. 표지는 첫 꼭지, 마감은 마지막 꼭지. 장 표지는 없음 |
| `emotion` | 대본 꼭지의 감정 그대로(있으면) — 도식은 그 감정에 맞게(`PROMPT.md` 2절) |
| `step` | 흐름 단계(공감대 · 가능성 · 성과 · 전문성 · 공통 문제 · 핵심 원리 · 객관적 근거 · 전략 · 커리큘럼 · 성공 사례 · 운영 · 관리) |
| `index` · `title` | 내지 목차 표시 · 대제목(24자 안쪽 한 줄, 결론) |
| `part` | 주 도식 — `PROMPT-PARTS.md`의 `##` 이름 그대로(`.m-orbs` · `.s-dialog` …) |
| `support` | 보조 글 방식 `.m-say` · `.m-bignum` · `.m-note` · `.m-memo` · `.m-caption` · `그래프 제목`, 없으면 `null` |
| `photo` | 사진 자리 장이면 `true`(사진 자리 부품을 쓰면 자동으로 셈) |
| `facts` | **그 장에 쓸 숫자를 모두**(대제목 · 도식 · 보조 글). 요청에 있는 숫자만, 계산한 값은 `"240분 = 2회 × 120분"`처럼 = 오른쪽에 식 |

## 검사가 보는 것

- 18 ~ 24장(대본이 있으면 목표 장 수 ±3), 1장 표지 · 마지막 마감 · 장 표지 2 ~ 3장
- 대본이 있으면 꼭지 순서대로 · 빠진 꼭지 없이 · 내지마다 `beat`
- 내지마다 목차 표시 · 대제목(26자 넘으면 ✗) · `PROMPT-PARTS.md`에 있는 부품
- 같은 주 도식 두 번까지 · 바로 옆 장 연속 ✗ — 보조 글 방식도 같음
- 서로 다른 주 도식 12종 이상
- **그림 도식이 사진 장을 뺀 내지의 절반 이상**(`PROMPT-PARTS.md` 머리의 분류 '그림')
- 사진 자리 장 2 ~ 4장
- `facts`의 숫자가 요청에 있는지, 대제목의 숫자가 `facts`나 요청에 있는지

## 고르는 요령

- 장마다 먼저 "이 내용을 그림으로 보이면 무엇이 되나?"를 묻는다 — 점수가 바뀐 것 = 원 크기 비교 · 시험지 두 장, 감점 = 첨삭 답안 · 채점표, 시험 = OMR · 시험 범위 · 종, 시간 = 달력 · 시계. 카드 · 단계 · 목록 · 질문과 답(분류 '정보')은 그림으로 보일 게 없을 때만.
- 장마다 "대제목이 말하는 것"을 먼저 정하고, 그 정보 모양에 맞는 부품을 고른다(`PROMPT.md` 4절). 남는 부품을 끼워 넣지 않는다.
- 요청 정보가 적으면 장을 줄인다 — 숫자 · 후기가 없는 단계는 빼거나 방법 · 원리 장으로 채운다.
- 주제다운 도식(수학 = 식 · 첨삭 답안 `.m-fix`, 국어 = 문장 분석 `.m-sentence`, 시험 = 시험지 `.m-papers` · 달력)을 한두 장.
