# 사진 보고 다듬기 (덱을 쓰는 Claude용 — 4단계)

검사(`slideCheck`)를 통과한 덱을 장마다 사진(960×540)으로 찍어 보낸다. 디자이너가 사진을 보고 고치던 것처럼, **검사로는 안 잡히는 약점**을 찾아 고칠 장만 고른다. 고칠 장이 없으면 "없음"이라고만 답한다.

## 답 형식

장마다 한 줄, 문제가 분명한 장만, **최대 5장**:

```
7장: 수업 시간 띠가 구간 하나라 휑해요 — 개념 · 유형 · 서술형 세 구간으로 나누기
11장: 대제목은 '같은 기준'인데 도식은 아이콘 칸 나열이라 내용이 안 보여요 — 채점표(.m-rubric)로 기준을 직접 보이기
```

`N장: 무엇이 문제인지 — 어떻게 고칠지`. 이 줄들이 그대로 다시 쓰기 요청(`PROMPT-FIX.md`)이 된다.

## 사진에서 보는 것 (중요한 순서)

1. **내용**: 대제목이 말하는 것을 도식이 그대로 보이나 — 아이콘 칸 · 카드 나열로 때운 장, 대제목과 상관없는 도식 ✗. 그림으로 보일 수 있는 내용(점수 변화 · 감점 · 시험 · 시간)을 카드 · 목록으로 쓴 장은 그림 도식으로.
2. **휑함 · 빈약함**: 도식이 작게 떠 있거나, 항목이 한두 개라 빈 곳이 넓은 장. 빈 곳은 장식이 아니라 내용(항목 · 단계 · 비교)으로 채운다.
3. **되풀이**: 두 장이 같은 말 · 같은 숫자를 되풀이하나, 이웃 장과 모양이 거의 같나.
4. **어색함**: 글이 너무 길어 빽빽한 칸, 한 칸만 두 줄, 짧은 이름이 두 줄로 꺾임, 강조(메인 면)가 두 곳 이상.
5. **주제다움**: 덱 전체에 주제다운 그림(시험지 · 첨삭 답안 · 문장 분석 · 달력)이 한두 장 있나 — 없으면 가장 무난한 장 하나를 그렇게.

간격 · 정렬 · 글자 크기처럼 키트가 맞추는 것은 고르지 않는다(검사가 이미 봄). 표지 · 장 표지 · 마감 · 사진 자리 장은 보지 않는다.
